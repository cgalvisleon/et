## Code style

Code must be understandable, maintainable and scalable by a human: clear names, short functions, one place per rule. GoDoc for every function, in English and **brief**: the function name + one or two lines on what it does (and why, when not obvious), one line for params, one for returns; no narration of the code or of the fix history (that goes in the spec). **But** most existing files (`et/json.go`, `jwf/`, `resilience/`, `stores/`) use a `/** ... @param ... @return ... **/` block style — match whatever the surrounding file uses.

## Architecture

Modular utility library for Go microservices: every directory is an independent package, no central entry point.

### Core type: `et.Json`

`et/json.go`: `Json` (`map[string]interface{}`) is the lingua franca of the whole library — typed accessors (`Str`, `Int`, `Bool`, `Time`, `Json`, `Array`…), default-value variants (`ValStr(def, keys...)`), nested traversal via variadic keys. **In goja scripts** (`et/goja.go`, 2026-10-19): `et.ToJS(vm, v)` turns a `Json`/`map[string]any`/`Item`/`Items`/`List` into a `goja.DynamicObject` over the same map (keys as properties, nested objects wrapped lazily and cached, changes made in JS land in the Go map) whose prototype (`et.JsonPrototype(vm)`, one per runtime) has every `Json` method by its Go name (`obj.ValStr("", "a", "b")`; a data key with a method's name hides the method); Go funcs are called with `GoArg`-converted args and `ToJS` results (a returned error is thrown; `func(goja.FunctionCall…)` goes as is) and structs become objects with Go-named methods/fields (the former `jwf` goObject). `et.FromJS`/`JsonOf` go back: an `et` object gives its same map, other objects a new `Json`, arrays `[]any`, integers `int64`. `ValAny`/`Get`/`ValJson`/`ArrayJson` also read a nested script object (`interface{ JsonValue() Json }`) that goja exported as is. `jwf` uses it everywhere (`GoValue`, `params`/`ctx`, `Run`) and keeps the old camelCase names (`str`, `set` merge, `view`, `omit`…) as aliases on the prototype (`aliasJson`). Objects now reach Go as `Json`, not `map[string]any`: every type switch on data must accept both (`et.ToWhere`, `SetNested` and `jsql.unwrap` were fixed for it; `bind` —`jsql.BindWrapper`— takes `any`, an object or a list such as a where). Test: `go test ./et/ -run TestJsonGoja`, `go test ./jwf/ -run TestRun`, `jsql/drivers/test` `TestStepScript` (sqlite: an engine-like update step with bind, where, returning, `ctx.put`/`view`). `TestWrapper/sqlite` (jsql) fails 3 checks (`rolledBack`, `query`, `missing`) also on the HEAD of 2026-10-19, before this change. `ScanRows` decodes `[]byte` and JSON-looking `string` values (`{`/`[` prefix). Parsing lives in `et/json.go` (formerly `parse.go`): `decodeJSON` (UseNumber, then numbers back to `float64` — kept for the many consumers that type-assert `float64` — except integers beyond 2^53, which stay `int64`) and `parseJSON` (also repairs raw control chars inside strings, text escaped once more, double encoding) back `ToJson`, `Scan`, `ScanRows`, `ValJson`, `ValArray`, `ArrayJson` and the `Item`/`Items`/`List`/`Wheres` round trips; `stringOf` (no `%f`: `"1"`, `"3.1"`), `intOf` (floats truncate, texts must be integral), `floatOfAny` and `boolOf` (1/0 and yes/no/si/on/off texts; other numbers give the default) back every typed accessor. Tests: `go test ./et/ -run 'Json|Bool|Floats|Integers|Other|Scan'`. **Conditions** (`et/spec.md`): evaluated in memory exactly as SQL does — one evaluator (`evaluate` in `evaluate.go`) behind `EvaluateObject`, `EvaluateValue` and `Wheres`, with AND binding tighter than OR; `ToConditions` makes a condition without connector after the first an `AND` (before, it was ignored in memory and broke the SQL); integers compare exactly (`compareNumbers`, also beyond 2^53); `like` takes `%`/`_` (and `*` as `%`), case insensitive; `between` takes `BetweenValue`, `{min, max}` or `[min, max]` (`ToBetween`, used by the five drivers; unreadable = `1 = 0`). `TestMemoryMatchesSql` in `jsql/drivers/test` checks memory = SQL. `Clone` is shallow (`DeepClone` copies nested objects/lists); `Put` into itself is a no-op; `SafeData.Trim(max)` keeps the newest (jsql's `AuditLog` uses it); `NewSafeMap`; `Wheres.AddResult` (`AdddResult` is a deprecated alias). **Files** (regrouped 2026-10-27, 8 + 4 tests): `json.go` (`Json`, JSON parsing, date layouts and `parseDate`, `Serialize`/`ToJson`/`ToString`), `result.go` (`Item`, `Items`, `List`), `condition.go` (types, constructors, field references, `ToCondition`, `Command`), `evaluate.go` (`ApplyTo*`, `evaluate`, exact numbers, `MatchLike`, `between`; public functions first), `where.go` (`Wheres`, `Source`, `From`, joins), `goja.go` (`ToJS`/`FromJS` + the script wrappers), `safemap.go`, `msg.go`. `et/result.go` holds the results: `List` is the paginated result (`Rows`, `All`, `Count`, `Page`, `Start`, `End`, `Result []Json`); `Item`/`Items` are single/multi result wrappers (an `Items` accessor with an index out of range gives its default, `Items.at`). Data types (`et.TypeData`, `et/condition.go`): `KEY` (VARCHAR 80), `TEXT`, `MEMO`, `INT`, `FLOAT`, `BOOL`, `DATETIME`, `JSON`, `BYTE`, `ANY`, `ARRAY`, `ARRAY_JSON|STRING|INT|FLOAT|BOOL|DATETIME`. There is no `GEOMETRY`/`EMBEDDING`/`STRING`.

### SQL builder / ORM: `jsql/`

- **Concurrency**: `DB.Schemas` (`muSchemas`; `getModel` never creates a schema, only `getSchema` when defining) and `AuditLog` (`muAudit`) are locked; definitions on a model are serialized by `Model.muDef` and replace its maps/`Columns` instead of writing into them (copy on write), because the drivers read them without locks. Indexes, keys, hiddens, omit-updates and the trigger scripts are still appended in place without `muDef`; the full rule set is the `Concurrency` block over `type Model` (`jsql/model.go`).
- **Files** (regrouped 2026-10-27, 13 files): `catalog.go` (public API), `connection.go` (Driver interface, `Tester`, connections, `Load`/`CreateDB`), `db.go` (DB, `Schema`, `Tx`), `define.go` (`Column`/`TypeColumn`, `Define`), `model.go` (+ default triggers, `Concurrency` block), `relation.go` (Detail, Master, Rollups, `QueryDetail`/`QueryRollups`, joins), `query.go`, `command.go`, `jquery.go`, `helpers.go` (+ condition constructors), `series.go`, `wrapper.go`, `msg.go`.
- `jsql.Load()` / `jsql.LoadTo(dbName, hostName...)` → `*DB`; config is read internally via `envar` (`DB_IS_DEBUG` reaches the `DB` through `ConnectParams.IsDebug` since 2026-10-27 —before, only `DEBUG` worked—; `SqliteConection.GetParams` now includes `id`, so a sqlite `DB` keeps `db:sqlite:<file>` like the other drivers) (`DB_TENANT_ID` is no longer read; only `create/template/templates.go` still writes it).
- Drivers in `jsql/drivers/<name>/`, self-register via `init()`, imported as side effect: `postgres` (`lib/pq`), `sqlite` (`modernc.org/sqlite`), `mysql`, `mssql`, `oracle` — each with the same file set (`connect`, `load` = DDL, `query`, `command`, `quoted`, `types`, `test`). `josefina` (2026-10-27, closes B5) embeds the postgres driver and connects with `lib/pq` to Josefina's Postgres protocol with `options=-c language=jql`; it cannot create/drop databases or drop models (`MSG_DRIVER_CANNOT_DROP_DB`, `josefina.ErrCannotDrop`); tested by `jsql/drivers/test` with `JOSEFINA_*` (default the docker compose cluster on 5433, `sslmode=require`), a fresh `jsql_t<n>` schema per run. A change to SQL generation usually has to be mirrored in all five (josefina inherits postgres).
- **Table names**: the core sets `Model.Table` (in `newModel` and `Model.Init`, `Model.setTable`) from `Driver.UseSchema()`: `schema.name` for postgres/mssql, `schema_name` for sqlite/mysql/oracle (no `CREATE SCHEMA`, tables live in the connection's database/user). Drivers build SQL from `model.Table`/`From.Table`, not `Schema`+`Name` (mssql splits it back to quote `[schema].[name]`). Raw SQL against a sqlite table must use the prefixed name (e.g. `main_tasks`).
- `jsql/catalog.go` is the whole public API in one file: every exported function/method is a thin wrapper over a private implementation elsewhere in the package, grouped into numbered sections. New public API goes there (and `TestCatalog` checks the sections). `jsql/spec.md` is the formal spec with a numbered gap list ("brechas", e.g. B8); `feature.md` is its source.
- `jsql/jquery.go` parses JSON query/command descriptors (`select`/`from`/`join`/`where`/…, `insert`/`update`/`delete`/`upsert`/`bulk`); `from` and join `to` take the standard object `{database, schema, model, as}` or the short text `"schema.model:as"` (one parser, `fromRefs`/`parseFromRef` + `DB.modelOf` in `query.go`; `database` must match the connection's); `jsql/wrapper.go` `Wrapper(db)` exposes jsql to goja scripts (triggers, `DefineCalc`) and `jsql/jsql.d.ts` is the matching TypeScript declaration — keep both in sync when changing the wrapper.
- `Driver` interface (`jsql/connection.go`): `UseSchema()`, `CreateDB`, `DropDB`, `Connect(db)`, `ExistModel`, `Load(model)` (DDL text), `Drop(model)`, `Query(query)` (SELECT text), `Command(command)` (DML text); all but `UseSchema` take `timeout ...time.Duration`. Optional `jsql.Tester` (see below).
- sqlite quirk: queries return each row as one JSON object; a nested JSON column inside it comes back double-encoded (see `ia/similarity.go` `chunkEmbedding`).

```go
model, _ := db.DefineModel("public", "users", 1, userId) // adds id, created_at, updated_at, _source, _idx

model, _ := db.Define(jsql.Define{                            // struct-based, preferred for complex models
    Schema: "public", Name: "users", Version: 1, IdxField: jsql.IDX,
    Columns: []jsql.Column{
        {Name: "email", TypeData: et.TEXT, Default: ""},
        {Name: "name", TypeColumn: jsql.ATTRIB, TypeData: et.TEXT, Default: ""},
    },
    PrimaryKeys: []jsql.DefIndex{{Name: "email", Sorted: true}},
    Unique:      []jsql.DefIndex{{Name: "email"}},
})
model.Init() // runs DDL

items, _ := model.Where(jsql.Eq("status", jsql.ACTIVE)).And(jsql.More("age", 18)).Limit(1, 20) // page, rows
item, _  := model.Where(jsql.Eq("id", id)).One()
_, _ = model.Insert(et.Json{...}).ExecTx(nil)   // also Update(...).Where(...), Upsert(...)
```

Manual alternative: `db.NewModel(...)` + `DefineColumn`/`DefinePrimaryKey`/`DefineUnique`/`DefineAttrib`/`DefineForeignKeys`. `db.LoadModel(schema, json)` and the JSON `define` descriptor build the same `Define`.

- **`TypeColumn`**: `COLUMN` (real column), `ATTRIB` (key inside `_source` JSONB, cast on read), `DETAIL`/`MASTER`/`ROLLUP` (virtual relations; `MASTER` goes through a bridge table; `DefineRollup(..., where ...*et.Condition)` filters `to`, ANDed to the keys —an `OR` keeps them: `rollupConditions` repeats the keys in each OR term—, a `{field: "x"}` value is read from the resulting row, and `rollup.OrderBy` picks the first record of a row/object rollup). With several rows, single-key relations are resolved in batches (`setRelations` in `relation.go`: one `WHERE fk IN (…)` query per 500 parents, aggregates with `GROUP BY`) and their errors are returned, `CALCFUNC` (Go `CalcFunction`), `CALC` (JS script run per row).
- **Column constants** (`jsql/define.go`): `ID`, `IDX` (`_idx`), `SOURCE` (`_source`), `RESULT`, `STATUS`, `VERSION`, `TENANT_ID`, `PROJECT_ID`, `CREATED_AT`, `UPDATED_AT`, `CODE`, `KIND`. `_idx` is the text of `time.Now().UnixMilli()` (`Model.getIdx`) set by an auto `BeforeInsert` trigger, not a sequence nor a UUID.
- **Status constants**: `ACTIVE`, `ARCHIVED`, `CANCELED`, `PENDING`, `APPROVED`, `REJECTED`, `OF_SYSTEM`, `FOR_DELETE`, `IN_PROCESS`, `FAILED`; `jsql.Status` is the map of valid ones, `jsql.StatusList()` lists them.
- **Triggers**: before/after × insert/update/delete, `TriggerFunction func(tx *Tx, old, new et.Json) error`.
- **Nested JSONB paths**: `"a->b->c"` field names are translated to `->`/`->>` chains with casts on ATTRIB leaves.
- `.Debug()` logs SQL and skips execution; `.Test()` generates SQL without executing (on `Model`, `Query`, `Command`).
- `jsql.DefineSeries(db, schema)` → series/code generator (`GenSerie`, `GenValue`, `SetSeries`, `Model()`). There is no `jsql.Store`/`DefineStore` anymore.

### HTTP servers

- **`server/`** — lightweight `chi.Mux` wrapper, no Redis/NATS.
- **`ettp/v2/`** — `ettp.New(name, *Config)`; `Config` has `Port`, `RpcPort` (zero = OS-assigned), `Parent`, timeouts, `AllowOrigin`, TLS, `Transport`, `Debug`. It does **not** call `cache.Load()`/`event.Load()` — callers must. Syncs router state across replicas over NATS (`EVENT_SET_ROUTER`/`REMOVE`/`RESET`; `m.Myself` prevents self-processing).
- **`ettp/v1/`** — older but not dead (has apigateway/proxy/token/cache files with no v2 equivalent); check which version a `cmd/` imports.
- **`router/`** — `router.NewApi(name, path, host, port, rpc, version)` → `*Api` over `chi.Mux`; `Public`/`Session`/`Protected(group, method, path, name, handler)`; `Api.Item(status, fn)`/`Items(fn)`/`List(fn)` wrap business functions; `UseAuthentication`, `UseAuthorization`, `UseLimitRate`. Used by `core-studio/api`, `postick/api` and `ettp/v2`.

### Infrastructure (external services)

- **`cache/`** Redis (`Set`/`Get`/`Delete`/`Pub`/`Sub`), **`event/`** NATS (`Subscribe`/`Publish`/`Stack`; `event.Log(channel, data)` publishes on that channel without blocking —until 2026-10-27 it always used `EVENT_LOG`, so `event.Error` never reached `event:set:error`—), **`graph/`** Neo4j.
- **`jrpc/`** — `net/rpc` over TCP; `jrpc.Mount(host, port, services, packageName)` with a simple `Solver` registry.
- **`tcp/`** — TCP client/server with concurrent `Send`/`Request` in both directions, `OnConnect`/`OnDisconnect`, and streams (`SendStream`, `RequestStream`, `ReceiveStream`) with credit-based flow control. Catalog layout (as in `store/`): private implementation (`link.go`, `client.go`, `server.go`, `stream.go`) + public wrappers in `catalog.go`. Identity: `NewClient(id, name)` / `NewServer(id, name)` (empty id → UUID, fixed for life); on connect both sides exchange a `msgHello` frame, so server-side conns carry the remote client's `ID()`/`Name()` and the client learns `ServerID()`/`ServerName()`. `hub.go` + `message.go` implement the Hub (spec §14, HUB-01…HUB-14, all verified): `NewHub(id, name)` groups servers (`LoadServer(port)`/`DownServer`) and clients (`ConnectTo(addr)`/`Disconnect`); typed `Message{From, Header, Type, Message}` (`TypeBeat/Int/Float/Text/Json`) sent with `Send(addr, msg)` / `SendTo(port, clientID, msg)` as JSON in a `msgSend` with a per-connection `seq`, delivered to `OnMessage(srv, conn, msg)` in order (out-of-order arrivals are buffered; the delivering goroutine drains); `OnConnect`/`OnDisconnect(srv, conn, …)` where `srv == nil` means a Hub-opened client; per-connection metrics (`Metrics(port)`), `Heartbeat(interval)` + `Status()` (3 missed beats close with `MSG_HUB_HEARTBEAT` via the private `closeWith`), shared `SetTimeoutServer/Client`, `Close()`. Used by josefina's `internal/node` for its cluster hub. Security (`security.go`, spec §7.4): `SetSecurity(Security{Secret, ServerTLS, ClientTLS})` on `Client`/`Server`/`Hub` (the Hub shares one `*security` pointer with its servers and clients, like the timeouts; applies to connections opened afterwards); with a secret the hello becomes three frames (client nonce → server nonce + HMAC proof → client proof), proofs bind both nonces, both ids and the TLS exporter of the session; `NewTLS(cert, key, ca)` builds TLS 1.3 configs (self-signed without files, mutual TLS with a CA); `ToJson` carries `tls`/`auth`. Docs: `tcp/spec.md` (protocol, API behavior and guarantees; §1–§14 implemented) and `brecha.md`. Conformance program: `go run -race ./test/tcp` (writes `test/tcp/result/`; fails if any public method is untested). Moved from josefina (`internal/tcp`) on 2026-10-21; replaces the old `jtcp` (Raft-style node), now removed. `cmd/server` and `cmd/client` are a minimal echo server and a stdin console over it. `NewTLS` with files re-reads the certificate, key and CA when they change (checked at each handshake; a broken file keeps the last valid one; mutual TLS verified in `VerifyConnection` against the current CA).
  **Every change to `tcp/` must update `tcp/spec.md` (and `brecha.md`) in the same change** (plus `test/tcp/test.go`'s `publicAPI` list and cases when the public API changes), bumping its "Versión del documento" line.
- **`websocket/`** — WebSocket pub/sub server and Go client on `github.com/gorilla/websocket`: `NewServer` (server-side connections are `Conn`) and `NewClient`/`Connect` (returns a `Client`); topic and queue (round-robin per group) subscriptions, publish from server or client, `OnConnect`/`OnSubscribe` (can reject) and `OnDisconnect`/`OnUnsubscribe`. Same catalog layout as `tcp/`. Moved from josefina on 2026-10-21 (not wired into josefina's server). Docs: `feature.md` (the goal), `spec.md` (normative, requirements WS-01…WS-13) and `brecha.md` (status of each requirement vs. the goal, plus out-of-scope next steps and a history). Verifier: `go run -race ./test/websocket` (writes `test/websocket/result/`; fails if a case fails, a requirement is untested or a public method is untested; case 12 checks the catalog layout by parsing the source). Replaces the old `jws`, now removed.
  **Every change to `websocket/` must update `spec.md` and `brecha.md` in the same change** (plus `test/websocket/test.go`'s `publicAPI`/cases when the API changes), then rerun the verifier and record the result in `brecha.md`'s history.

### Utility packages

- **`envar/`** — `GetStr/GetInt/GetInt64/GetFloat/GetBool` with defaults, `Arg*` for CLI args, `Validate([]string)`. The old `config/` package is gone (only stale strings remain in `create/template/templates.go`).
- **`logs/`** (`Info`, `Alert`, `Error`, `Debug`, `Fatal`→`os.Exit(1)`, `…f` variants) over **`stdrout/`**.
- **`jwt/`** (tokens stored in `cache`) over **`claim/`** (HS256, `SECRET`).
- **`crontab/`** — event-driven; `crontab.Load(tag, store)` sets a package singleton, then `crontab.CronJob(tag, ownerId, spec, repetitions, params, fn)` (spec is a cron text: 5 fields get second 0, 6 fields or `@daily`/`@every 1h`; `ParseSpec` validates and normalizes, `NextOf(spec, from)` gives the next run) / `ScheduleJob(tag, ownerId, at time.Time, params, fn)` (`at` must be future). Both return the `*Job`; **the job id is the tag** and registering the same tag again replaces it everywhere (every job carries a `rev`; the `crontab:remove` sent before `crontab:set` keeps that rev, because NATS delivers each subscription on its own goroutine and the remove may arrive after the set). `RemoveJob(tag)` removes it. A job registered with `CronJob`/`ScheduleJob` is scheduled **in the process that registers it** (`register` → `crontab.addJob`, since 2026-10-19; before, the `crontab:set` queue gave it to any instance, so whoever kept its state might not hold it); other instances drop theirs via `crontab:remove`. Each shot is published on `job:<tag>` and handled through the queue `QUEUE_JOBS` (once among instances, one subscription per tag: `event` keeps one subscription per channel, so the old one is unsubscribed first). `repetitions` 0 = unlimited; the count lives in memory. Jobs are not reloaded from the `Store` on start: the caller registers them again (core-studio's engine loads them from its `calendars` model). `go mod tidy` run on 2026-10-19 (dropped the charmbracelet/clipboard deps left by the removed `cmd/jcli`). HTTP handlers publish control events. Tests: `NATS_HOST=localhost:4222 go test ./crontab` (2026-10-19, also checked with two processes: one shot per second, the second registration replaces the first). Note: `timezone.Parse` takes a key of its layouts table, not a Go layout (that broke `ScheduleJob`; `job.start` now uses `time.Parse(time.RFC3339, …)`).
- **`validator/`** — fluent validator (`jval/` no longer exists). ### `store/` — append-only WAL key/value store

A **single-node**, concurrency-safe, append-only (WAL-style) store of `id → []byte`. It came from Josefina (`internal/store`, its first storage engine) on 2026-10-25, when Josefina kept only Pebble. Replication lives *above* it (the consumer ships `WalSince` entries and applies them with `ApplyWalEntry`), not inside it. It stores raw bytes; JSON encoding is the caller's job. Doc comments in this package are in Spanish.

**Spec:** `store/spec.md` is the package's reference (on-disk format, per-operation guarantees, compaction, recovery, known defects). **Every change to `store/` must update `store/spec.md` in the same change** (plus the store section of `README.md` and `doc/README.es.md`, and this section, when the API changes), bumping its "Versión del documento" line. It also lists open defects (none open now; `Empty` deleting the snapshot was fixed on 2026-10-13).

#### Public API (this is the whole surface; everything else is private on purpose)
Every public function/method lives in `catalog.go` as a thin wrapper, grouped by section (Apertura y ciclo de vida, Escritura, Lectura, Mantenimiento, Monitoreo, Replicación, Utilidades). The real implementation is a private function/method with the same name lowercased (`open`, `recover`, `normalize`, `insert`, `close`, `forEach`, `walSince`, ...) in its own file (`store.go`, `compact.go`, `notify.go`, `wal.go`, `recover.go`). Code inside the package calls the private names. To add a public operation: implement it privately, then add the wrapper to `catalog.go` in its section. The debug flag field is `debug` (the name `isDebug` belongs to the method). Note that the private `recover` shadows Go's builtin inside this package — a `recover()` for panics there would need renaming it first.

| Call | Semantics |
|---|---|
| `Open(pathData, pathWald, name, mode)` | Opens/creates. Segments in `pathData/segments/<name>/`; `pathWald/{snapshot,compact,recover}/<name>/`. `name` goes through `Normalize`. `ReadOnly`/`ReadWrite`. In `ReadWrite` it self-repairs after a crash: `repairCompaction` (shared with `Recover`) before creating dirs, and `repairTail` truncates the **active** segment at its last valid record (bytes copied to `recover/` via `quarantineTail`, logged as `open:repair`). Sealed segments can't be torn (rotation fsyncs before creating the next) and are left to `Recover`. |
| `Close()`, `Empty()` | `Close` waits for compaction, fsyncs and retires all segments. `Empty` closes and deletes the data dir and the snapshot (reopening gives an empty store with WAL 0). |
| `Insert(id, data) (bool, error)` | Writes only if `id` is absent. |
| `Update(id, data) (bool, error)` | Writes only if `id` exists **and** the bytes differ (identical data → no log write, returns `false`). |
| `Delete(id) (bool, error)` | Writes a tombstone only if `id` exists. |
| `Deferred() Deferred`, `WaitDurable() error` | `Deferred()` gives `Insert`/`Update`/`Delete` with identical semantics and visibility that return without waiting for their fsync; `WaitDurable()` waits until everything written so far is on disk (shared group-commit fsync; no-op without `SYNC_ON_WRITE`, fine after `Close`). A `Deferred` writer must call `WaitDurable` before confirming — e.g. release the caller's own lock first, then wait for the disk. |
| `Get(id) ([]byte, bool, error)`, `GetVersion(id) ([]byte, uint64, bool, error)`, `IsExist`, `Count`, `Keys(asc, offset, limit)` | Reads. `limit <= 0` = no limit. `GetVersion` adds the LSN of the id's last record (0 if absent): its version for optimistic concurrency. |
| `ForEach(fn, asc, offset, limit)` | Disk reads run concurrently on `min(NumCPU, n)` goroutines, but `fn` is called **sequentially, in key order, on the caller's goroutine** — it needs no locking, and returning `false` stops exactly there. The record set is fixed at call start; no lock is held, so `fn` may call back into the store. |
| `Stats() et.Json` | `count`, `size`, `wal`, `tomb_stones` plus operations in flight: `reading` (Get/ForEach), `inserting`, `updating`, `deleting` (writes waiting for `writeMu` count as in flight). |
| `OnStats(fn func(et.Json))` | Hooks `fn` to receive `Stats` whenever in-flight counts change. Called from one background goroutine, coalesced to the latest state; never slows operations. Stops on `Close`. |
| `Sync(fn func(Change))` | Hooks `fn` to receive every applied `Insert`/`Update`/`Delete` (also those arriving via `ApplyWalEntry`) as `Change{Op, ID, Data, LSN}` with `Op` = `OpInsert`/`OpUpdate`/`OpDelete`. Called **under `writeMu`** right after log + index are written, so changes arrive in exact LSN order with no gaps — the outbound side of a multi-node setup (`ApplyWalEntry` is the inbound side). `fn` must be fast, must not write to the same store (deadlock), and must copy `Data` if it keeps it. No-op writes (Update with identical bytes, Delete of a missing id) emit nothing. |
| `Compact()` | Manual compaction (also automatic when tombstones > max(10% of keys, `MIN_THRESHOLD_COMPACT`)). |
| `WalSince(lsn)`, `ApplyWalEntry(e)`, `WalEntry` | Replication primitives (log shipping by LSN), for log shipping between nodes. |
| `Recover(pathData, pathWald, name) (et.Json, error)` | Offline repair of every segment (`Open` already covers compaction + the active one); the store must be closed everywhere. Restores/cleans an interrupted compaction, drops the snapshot, and truncates each segment at its last valid record after copying the bad tail to `pathWald/recover/<name>/`. Returns a report. |
| `ToJson`, `ToString`, `Debug` (`IsDebug` is its deprecated name), `Normalize` | Status/debug helpers; `Normalize` is also used by `jdb` for names. |

There is deliberately **no upsert**: callers compose it as `Update`, then `Insert` if the id did not exist (and `Update` again if that `Insert` lost a race).

#### On-disk format
- Record: `[LSN:8][DataLen:4][CRC:4][IDLen:2][ID][Status:1][Data]`, big-endian; `Status` is `Active` or `Deleted` (tombstone, no data). **The CRC covers `Data` only**, not LSN/ID/status.
- Segments `segment-%06d.dat`, rotated at `RELSEG_SIZE` MB (default 128). A new snapshot is written on every rotation.
- Snapshot `state-<name>.snap` (version 2): index of all non-active segments plus the WAL counter, CRC-protected. Optional — if missing or corrupt, `Open` rebuilds the index by scanning every segment.
- Scans stop silently at the first torn/corrupt record (see `segment.scan`), which is also how `Recover` finds the valid end.

#### Concurrency invariants (keep these when changing the package)
- `writeMu` serializes every mutation, and a mutation's existence check + log append + index update happen under **one** hold (`put`, `appendRecordLocked` require it held). Lock order is always `compactMu` → `writeMu` → `indexMu`.
- Group commit (`commit.go`): every mutation (and `applyWalEntry`) runs inside `commit(wait, fn)` (`wait=false` for the `Deferred` view; `waitAll` = `WaitDurable`); `appendRecordLocked` does **no** fsync, only bumps `appended`. After releasing `writeMu`, `waitDurable(seq)` waits until `synced >= seq`; with no fsync in flight the caller becomes leader and `syncActive` fsyncs the active segment (read with `appended` under `indexMu.RLock`, pinned with `acquire`) covering everything appended so far. `syncMu` is never held across the fsync or together with `writeMu`. Writes are visible (index, `Sync` hooks) before their fsync; the caller returns after it. The first fsync error is sticky (`syncErr`).
- `indexMu` (RWMutex) is the *structure* lock: per-id operations (`get`, `getVersion`, `getIndex`, `setIndex`, `deleteIndex`) take it **shared** plus the lock of the id's shard; changing `segments`/`active` or replacing the whole `index` (rotation, compaction swap, snapshot load, `Empty`) takes it exclusively. `index` is a `*shardedIndex` (`index.go`, 64 shards by `maphash` of the id); whole-index reads (`len`, `clone`, `sorted`, `each`) lock every shard at once, in order. Lock order: `compactMu` → `writeMu` → `indexMu` → shards (ascending). Index mutations still all happen under `writeMu`.
- Segments are `mmap`ed read-only (`mmap_unix.go`; `mmap_other.go` falls back to `ReadAt`): sealed ones by `mapReadOnly` (on `seal()` and, at `Open`, every segment but the last; all in `ReadOnly`), the active one by `mapActive(MaxSegment)` (new segment, last one at `Open`, after the compaction swap) with a capacity larger than the file. `segment.visible` (atomic, bumped after each `write`) bounds what `readAt` copies from `mapped`; a read not fully inside it goes to `ReadAt` (never touch the mapping past what was written: beyond EOF it faults). The unmap happens in `segment.close()`, which only runs with no readers.
- `recordRef` carries the data CRC (`hasCRC`; refs loaded from the snapshot have none): `update` skips reading the old value when `ref.differs(data)`.
- Readers **never hold `indexMu` during disk I/O**: they look up the ref and `acquire()` its segment under `RLock`, release the lock, read, then `release()`. Compaction and `Close` call `retire()` on old segments instead of closing them; the file closes when the last reader releases it. Never close a segment that might still have readers.
- Segment writes are synchronous (`os.File.Write`), so a ref published in the index is always readable. The first write error is sticky.
- Shared counters `WAL`, `TombStones`, `Size`, `appended` and the in-flight counters are `counter[T]` (atomic inside, `counter.go`); use `inc`/`dec`/`add`/`count`/`set`/`setMax`, never the fields. The index goes through `getIndex`/`setIndex`/`deleteIndex`/`countIndex`; `...Locked` variants are for callers already holding `indexMu`.
- In-flight counters use `defer s.track(&s.<counter>)()` at the top of each operation's private implementation; `commitLocked` releases `writeMu` with `defer`, so a panicking `Sync` hook cannot leave the lock held.
- `Compact` runs in 3 phases: (1) under `writeMu`, copy the index and record the cut point (segment + offset); (2) without locks, copy live records to a temp dir; (3) under `writeMu` + `indexMu`, replay everything written after the cut (Puts copied, Deletes written as tombstones), delete the snapshot, swap directories, retire the old segments, rebuild the snapshot. It keeps the newest tombstone so the WAL counter never regresses on rebuild.

#### Known limitations (accepted, not bugs to "fix" unasked)
- One writer at a time in the log; with `SYNC_ON_WRITE=true` (default) concurrent writes share one fsync (group commit), but a lone write still pays the full disk latency, and data is visible before its fsync.
- The `writeMu` holder does a `write(2)`; when in-process readers spin without pause on every CPU it waits for a P on return and writes collapse to hundreds/s (`go run ./test/storebench -w 1000` vs. `-think 1ms`). Not seen with readers that block between ops (network).
- Compaction drops tombstones and overwritten records, so a replica behind the cut cannot catch up with `WalSince` (it would miss deletes); a replicating consumer must detect it (Josefina compared counts at the end of a catch-up) and send a full copy.

#### Testing the store
There are no committed tests. For ad-hoc tests: after `Open`, set `fs.MaxSegment` to a few KB to force rotation; use `t.Setenv("SYNC_ON_WRITE", "false")` for speed and `MIN_THRESHOLD_COMPACT` to control auto-compaction; always run with `-race`. Reopen the store at the end and compare against the in-memory state — that is how every change to this package has been verified. Throughput: `go run ./test/storebench` (`-w` workers, `-r` readers, `-think` reader pause, `-d` duration; `PROF=file` for a CPU profile).

### `jwf/` (workflows)

```go
wf, _ := jwf.New("")
wf.NewFlow("add", "add item", "1.0.0", ownerId, userId).
    Step("add", "step 1", func(instance *jwf.Instance, ctx et.Json) (et.Json, error) { return ctx, nil }).
    Step("add", "step 2", fn)
// Run(tag, triggerTag, id, code string, ctx, tags et.Json, await bool, userId string)
result, err := wf.Run("add", "add", reg.GetULID(""), "", et.Json{}, et.Json{}, true, userId)
```

- **`params` and `ctx` in a script are goja dynamic objects** (2026-10-11, `jsonObject` + `jsonMethods` + `jsonBinder` in `jwf/wrapper.go`, over `Step.Params` and `Instance.Ctx`): `ctx.user.name` reads and `ctx.total = …` writes, `JSON.stringify(ctx)`/`Object.keys(ctx)` list the keys, and the methods (`str`, `int`, `get`, `set`, `json`…) still work — a method hides a key with the same name (read it with `ctx.get("str")`). Values go out through `plainOf` (an `et.Json`, nested too, becomes `map[string]any`: goja would expose the named type with its methods and no keys), so a nested change (`ctx.user.name = …`) does not persist: reassign the top key or use `set`. Passed to Go (`console.debug(params)`, an `et.Json` argument) it shows its values (`String`/`MarshalJSON`). It is built per run through `jwf.Binder` (`func(vm *goja.Runtime) goja.Value`): a binding of that type is called by `RunCode` with the runtime instead of being set as is.
- **Console output** (2026-10-11, `jwf/console.go`): `consoleOf(prefix, emit)` builds the `console` binding (`log`, `debug`, `info`, `warn`, `error`; each argument a string as is or json) that writes to the server log and, with `emit`, sends a line `{level, message, at}` (message cut at `MAX_LOG_MESSAGE`, 4096). `Instance.OnLog(fn)` gets the lines of every step of the instance (with `step_id`, `instance_id`); `Step.OnLog(fn)` the lines of a step run alone (`RunScript(nil, …)`, a Test: it sets its own `console` then). `RunScript` returns the instance `Ctx` when it has one and, alone, the completion value of the scripts (the last expression, `RunScripts` → `RunCode`) when it is an object (`objectOf`: a JS object exports as `map[string]any`); anything else gives `{}`.
- **Go values handed to goja as they are** (checked 2026-10-11): an `et.Json` returned by a Go function (`db.Query(...).Result[0]`, `Json`, `.Json("x")`) is a Go object with its methods (`.Str("name")`, `.ToString()`) but its keys are **not** readable (`row.name` is `undefined`, `JSON.stringify(row)` is `{}`); `timeNow()` is a `time.Time` (`.Format`, `.Unix`), not a `Date`. (`validator()` has its own wrapper since 2026-10-11.) Only `params`/`ctx` (`jsonObject` + `plainOf`) give plain objects.
- First `Step` becomes a trigger; the next ones chain through output connections. `Flow.Error(...)` attaches an error-port step to the last step. A step runs a Go `fnStep` or a JS script (`RunCode`/`RunScripts`, goja, with `cache`/`fetch` bindings from `wrapper.go`).
- Instances are stored in Redis under `instance:<id>` (`cache.SetObject`, no TTL); `GetInstance` loads one or creates it, `RunInstance` runs it, `StopInstance(id)` sets `instance:<id>:stop` for `TimeAwait`. `Run` returns only the result ctx: pass your own id to read the instance afterwards. Status: `CREATED`, `PENDING`, `RUNNING`, `ROLLBACK`, `DONE`, `FAILED`, `CANCEL`, `COMPLETED`.
- On a step error it retries through `resilience` when `Flow.TotalAttempts != 0`, then follows the error connection.
- `AuditLog []et.Json` + `onChange` hooks (`MAX_AUDIT_LOG`, default 1000) is a reusable pattern; `jwf/step.go` (`Step`) and `jwf/flow.go` (`Flow`) are the reference implementation.
